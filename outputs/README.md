# 報修欄位表

檔案：`outputs/報修欄位表.xlsx`（相對於專案根目錄）。來源：根目錄的 `報修需求筆記.txt`。

以 Excel 或相容軟體開啟：
- 「欄位」包含 7 個欄位的欄位名、型態、必填、說明、範例。
- 「範例資料」含 10 筆全為虛構的資料；類別、緊急程度、處理狀態可使用下拉清單，清單驗證涵蓋第 2 列至工作表最後一列。
- 筆記未明訂的規格標為「待確認」。資料型態括號內為建議，並非已確認需求；未擅自設定必填規則。下拉清單暫允許空白，必填規則待確認。
- 範例時間是固定的虛構資料，不會在填寫時自動產生；正式系統依筆記應自動產生登記時間。範例時間格式僅供展示，時區、精度與正式格式待確認。
- 三種狀態均有範例，僅供資料展示，不代表本次示範已開放更新狀態。初始狀態待確認。

## 筆記中的矛盾或敘述不一致

1. 同事可讀權限：使用方式寫「一般同事：只能『新增』一筆報修」，資料安全卻寫「任何人可以讀取清單」。一般同事是否也能讀取清單待確認。
2. 狀態更新能力：背景與管理員使用方式要求「標示處理狀態／更新狀態」，本次示範卻限定「只做新增與清單」且「不能修改或刪除」。若前者描述完整系統、後者描述本次示範，便可相容；兩者適用範圍待確認。
3. 狀態更新者：使用方式已指定「管理員」更新狀態，但「還沒決定的事」仍列「狀態由誰更新」。責任歸屬是否已確認待確認。

「是否需要登入」尚未決定與「本次示範先不做登入」可以分別指長期需求與本次範圍，因此不單列為矛盾。
